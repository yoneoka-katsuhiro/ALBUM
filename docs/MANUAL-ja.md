# ALBUM 日本語マニュアル — 0.3.0

## 1. 作業フォルダーを用意する

ZIP全体を「書類」など書き込み可能な場所へ展開します。実行ファイル、`_internal`、`exiftool`は一緒に置いてください。写真を`input_image`へ、任意のGPSログを`input_gps`へ入れます。ALBUMは必要に応じて`output`を作成します。重要な写真は別の場所にもバックアップしてください。

標準の作業場所は実行ファイルの隣です。ソース実行では`album.py`の隣です。別の場所を使うには`--project-dir "/path/to/my photos"`を指定します。その中に同じ3フォルダーを置きます。空白を含むパスは引用符で囲みます。データフォルダーのシンボリックリンクや、内部のリンクファイルには対応しません。

macOSはターミナルで`./album`、WindowsはPowerShellで`.\album.exe`を実行します。以下の例はmacOS表記です。Windowsでは先頭を置き換えてください。ソース利用時は`python album.py`とし、ExifToolを別途インストールします。

## 2. 写真を整理する

```bash
./album --photographer yoneoka --location yakushima
```

コピー時は`--photographer`が必須です。`--location`の省略値は`unannotated`です。この2項目には半角英数字・ハイフン・アンダースコアだけを使います。元の写真名には日本語なども使えます。

入力パスの日本語・アクセント付き文字・空白はUTF-8でExifToolへ渡すため、Windowsのコードページを変更する必要はありません。パスにCR・LF・NUL制御文字がある場合はExifTool起動前に拒否します。ExifToolが制限を案内しているU+FFFF超のUnicode文字を含むWindows名は、対応保証の対象外です。リダイレクトした実行ログもUTF-8になります。

ALBUMはサブフォルダーも検索し、`DateTimeOriginal`、`CreateDate`、`FileModifyDate`の順で日付を取得します。整理に使う日付は、そのタグに記録された暦日です。時差による日付換算はしません。`FileModifyDate`は更新日時であり、撮影日時の証明にはなりません。どの値も有効でなければ`unknown_date`を使います。

同じ日付・撮影者・場所の中では時刻、ファイル名の順に並べ、`0001`から`9999`までの連番を付けます。既存番号の続きから開始し、既存ファイルを上書きしません。`9999`を超える場合はエラーにします。

```text
output/
└── 20260102_yakushima/
    ├── 20260102_yoneoka0001_yakushima.jpg
    └── 20260102_yoneoka0002_yakushima.jpg
```

対応拡張子は`jpg jpeg png heic tif tiff dng cr2 cr3 nef arw raf rw2`です。大文字・小文字は区別しません。隠しファイルとAppleDoubleファイルは無視し、他の形式は報告して残します。RAW・HEICへのGPS書き込み可否はExifToolと個々のファイル形式によります。JPEGの検証だけで全機種のRAW対応を確認したわけではありません。

コピーはSHA-256で検証します。`output`全体と今回の入力内で完全一致した内容を重複とみなします。見た目が似ている写真や縮小版は別ファイルです。隠しファイル`.写真名.album.json`は、元のハッシュとGPS付与後の出力を関連付けます。GPS付与後の重複検出を維持するため、この記録も出力ライブラリと一緒に保管します。外部編集で出力ハッシュが変わると関連付けを無効と扱います。

`--remove-input`を付けると、コピー検証後、入力ハッシュを再確認してから元ファイルを削除します。重複、非対応形式、失敗したコピーは削除しません。別のバックアップを用意してください。同じプロジェクトに複数のALBUMを同時実行したり、処理中のファイルを他ソフトで編集したりしないでください。

## 3. GPSを付ける

時刻付きGPSログを`input_gps`に置いて実行します。

```bash
./album --photographer yoneoka --location yakushima --geotag --gps-timezone +09:00
```

すでに整理した出力だけに付ける場合:

```bash
./album --geotag-only --gps-timezone +09:00
```

**0.3.0の標準対象は`output`だけです。** 過去に整理した写真も対象になります。入力原本にも付ける場合だけ`--geotag-input`を追加します。この場合は`sample.jpg.album-original`のような検証済みバックアップを原本の隣に残します。既存バックアップは上書きしません。すでに存在する場合はその入力へのGPS書き込みをエラーにするため、まず内容を確認してください。

有効な緯度・経度がある写真は変更しません。書き込み対象は一時コピー上で編集し、GPS値を再読込して確認した後に置き換えます。失敗した場合は元の対象ファイルを残し、エラーを数えます。

### 時刻と照合の規則

- 撮影日時には`DateTimeOriginal`か`CreateDate`を使います。ファイル更新日時はGPS照合には使いません。
- EXIFの`OffsetTimeOriginal`、`OffsetTimeDigitized`、日時末尾の時差を尊重します。時差がない場合は`--gps-timezone`の現地時刻として扱います。
- `+09:00`、`--gps-timezone=-05:00`のように固定時差を明示することを推奨します。省略するとコンピューターの**現在の**時差になります。過去の夏時間やIANAタイムゾーンは推定しません。撮影中に時計のタイムゾーンを変えた場合は、入力を分けて処理します。
- NMEA RMCはUTCです。時差付きGPX・KML・GeoJSONの日時はカメラのタイムゾーンへ変換します。時差のない値はすでに現地時刻として扱います。
- 時間差の上限は標準300秒です。`--gps-max-gap-seconds 120`で変更できます。0では完全に同時刻の点だけが該当します。
- 前後の点が同じログに属し、両方が上限内なら緯度と経度を線形補間します。経度は日付変更線をまたぐ短い方向を使います。それ以外は上限内の最も近い点を使い、同距離なら前の点を選びます。
- 地形や測地線を考慮した経路推定ではありません。同一ログ内の欠測区間を補間することもあります。複数機器・重なる旅行・長い欠測を混ぜないでください。時計のずれ、移動速度、GPS精度のモデルはありません。

### GPSファイル形式

| 形式 | 必要な内容 |
| --- | --- |
| `.log` | 有効な`$GPRMC`または`$GNRMC`。存在するチェックサムは検証します。チェックサムなしも受け付けます。 |
| `.gpx` | 座標と`time`を持つ`trkpt`、`rtept`、`wpt`。 |
| `.kml` | 時刻付き`gx:Track`、または時刻付きPoint placemark。地図に線が見えるだけでは時刻照合できません。 |
| `.geojson`、`.json` | FeatureまたはFeatureCollection。時刻プロパティは`time`、`time_created`、`timestamp`、`coordTime`、`updated_date`。数値はUnix秒です。座標の4番目もUnix秒として解釈しますが、これは標準GeoJSONではなく対応拡張です。 |

座標は緯度・経度の度数で、WGS84相当を仮定します。他の座標系からの変換はしません。利用できない点は除外し、読めないファイルはエラーにします。時刻付きの点がないファイルには`GPS_NO_TIMED_POINTS`と表示します。

## 4. CSVと表示を確認する

各出力フォルダーに`album_gps.csv`を作成します。`--geotag-input`使用時は入力分を`output/input_image_gps.csv`へ出します。

| 列 | 意味 |
| --- | --- |
| `photo_name` | プロジェクトからの相対パス。サブフォルダー内の同名写真を区別できます。0.2.1のファイル名だけの形式から変わりました。 |
| `shot_date` | 撮影日時。明示時差がある場合は選択タイムゾーンへ変換します。UTC接尾辞は付きません。 |
| `latitude`、`longitude` | 度数、小数点以下8桁。利用できない場合は空欄。 |

桁数は位置精度を保証しません。CSVはGPS処理のたびに更新し、その回の処理対象を記録します。履歴監査ログではありません。研究の来歴管理には実行ログと元のGPSログも保存してください。位置情報は希少種などの採集地点を示すため、共有前に内容を確認してください。

`COPIED`はコピー完了、`SKIPPED_DUPLICATE`は重複除外、`GEOTAGGED`はGPS付与です。`GPS_NO_DATETIME`は撮影日時なし、`GPS_NO_MATCH`は時間差上限内に点がないことを表します。`Errors: 0`は処理エラーが報告されなかった意味で、推定地点の正確性を保証しません。終了コードは完了0、処理・入出力エラー1、引数エラー2です。Ctrl+Cで中断できます。再開前に出力を確認してください。

## 5. 全オプションと復旧

| オプション | 用途 |
| --- | --- |
| `--project-dir PATH` | 3つのデータフォルダーを置く場所。 |
| `--photographer NAME` | 撮影者名。GPS専用実行以外では必須。 |
| `--location NAME` | 場所名。省略時`unannotated`。 |
| `--remove-input` | 検証成功かつ変更のないコピー元を削除。 |
| `--geotag` | コピー後、出力にGPSを付与。 |
| `--geotag-only` | コピーせず既存出力にGPSを付与。`--remove-input`と併用不可。 |
| `--geotag-input` | 入力原本も対象とし、`.album-original`バックアップを保存。 |
| `--gps-timezone OFFSET` | カメラの固定UTC時差。 |
| `--gps-max-gap-seconds N` | 時間差上限、標準300秒。 |
| `--version`、`--help` | バージョン・引数説明。ExifToolなしでも表示。 |

ExifToolが見つからない場合は配布フォルダー全体を再展開するか、ソース用のExifToolを導入します。権限エラーでは書き込み可能な作業フォルダーを指定します。GPS書き込み失敗時は対象の元ファイルが残ります。入力GPS編集を戻す場合はALBUMを停止し、編集後ファイルを別に保管してから、`.album-original`を元の名前で復元してください。標準の出力だけの編集は、旧出力を別途保管してから入力原本を整理し直せます。

不具合報告にはOS、ALBUMのバージョン、コマンド、期待結果、実際の結果、機密性のない最小例を添えてください。公開したくない写真や位置情報は添付しないでください。
